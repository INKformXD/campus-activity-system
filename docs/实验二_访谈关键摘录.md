# 实验二访谈关键摘录

日期：2026-10-10。访谈对象为作业包中的“模拟需求访谈”程序角色，以下是与需求判断直接相关的原回答摘录，不代表真实受访者的真人访谈；重复或偏题回复未收入。

## 学生用户

- 问：热门活动报名遇到什么困难？
  答：“有些热门活动确实很快就满了，我稍微晚一点看到，基本就报不上了。”
- 问：活动满员但仍想参加怎么办？
  答：“如果活动满了，我愿意先等一等，也希望知道自己是不是还在等待。具体顺序怎么定，我只知道应该由活动老师说明。”
- 问：报名后状态变化指什么？
  答：“普通活动一般比较直接，但有些活动提交以后不能马上确定能不能参加，我有时看不明白自己现在是什么情况。”
- 问：参加条件由谁决定？
  答：“具体人数和参加条件不是学生决定的，要看活动老师怎么组织，这个问题可以问活动组织教师。”

## 活动组织教师

- 问：哪些报名需要审核？
  答：“不是所有活动都要审核。有明确参加条件时，我才需要逐个确认报名学生是否符合。”
- 问：满员时如何处理仍想参加的学生？
  答：“活动已经满员时，可以先保留这些仍想参加的学生，让他们处在候补中。”
- 问：候补顺序如何确定？
  答：“候补要有明确先后，简单一点就是按进入候补的时间处理，先进入的人排在前面。”
- 问：已确认学生取消后如何补位？
  答：“已经确定参加的学生取消后，正式人数会少一人，也就空出一个位置。”
- 追问候补如何获得空位，答：“如果已经有人在候补，空出来的位置就按候补顺序给最前面的人。”

## 系统管理员

- 问：管理员主要负责什么？
  答：“我主要负责校园活动管理系统的平台管理，包括用户账号、角色和平台活动信息的日常维护。”
- 问：能否代替教师审核参加资格或调整报名规则？
  答：“当前业务规则里没有明确这一项，我不能据此补充新的需求。”
- 追问具体管理边界，答：“我主要看平台账号、用户角色和活动信息是否正常。V1.0 基本能够运行，但用户和活动多起来以后，管理边界就更重要了。”

## 尚未确认

模拟访谈没有确认候补升位是否需要学生再次接受、响应时限、站内/站外通知渠道、拒绝原因，以及管理员可修改的具体活动字段。V2.0 只更新系统内状态并按顺序补位，不实现通知及响应时限规则；管理员继续限定于平台管理范围。
